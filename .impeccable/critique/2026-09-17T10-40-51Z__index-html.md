## Anti-Patterns Verdict

**LLM assessment.** It no longer reads as AI-generated. The shell is a real pattern (Airbnb's search page), the copy is Jan's own voice, and the one accent is used for state rather than decoration. Two residues remain: the map is still decoration-by-density (227 equal dots), and "A hand-picked map of independent spots" in the bar is immediately restated as "227 places, hand-picked" above the grid.

**Deterministic scan.** `detect.mjs` on `index.html`: 1 finding, `overused-font` (warning, line 12) — the Google Fonts Inter stylesheet. It is a true positive with a twist: the page loads Inter and then never uses it. `font-family` is `Circular, -apple-system, system-ui`. A dead network request left over from the Framer branch.

**Visual overlays.** Not attempted: the browser pane's evaluate surface is read-only for injection in this session, so no user-visible overlay exists.

## Overall Impression

The layout change did the heavy lifting. Cards two-up, one bar, a rail, a result line: the thing finally reads as a tool rather than a landing page, and eight places fit where four did. What is still unfinished is the right-hand half. The map carries 227 equal dots and no way to read them, so it works as decoration and as a rough density plot, but not as an instrument. The single biggest opportunity is making the map and the list one interface instead of two things side by side.

## What's Working

- **The two-level filter, now that it partitions.** Eight families that add to 227, one open at a time, tags underneath only when they can narrow something. The counts are trustworthy, which is what makes a filter rail usable at a glance.
- **The card as a unit of judgement.** Category, name, note, tip, link. Nothing decorative, and the tip rule in Rausch gives the one piece of advice a place to live.
- **"Still on my bucket list" replacing the address.** The card now says something true in Jan's voice instead of repeating what the map already shows.

## Priority Issues

**[P1] Cards are not operable by keyboard**
- *Why it matters*: `.row` is a `div` with a click handler, `tabIndex -1`, no `role`. Tab goes from the search field straight past 227 places to the map controls. A screen reader announces a paragraph, not a button. The list-view items already do this correctly (`role="button"`, `tabIndex 0`), which makes the grid the odd one out.
- *Fix*: give each card `role="button"`, `tabindex="0"`, an `aria-label` of the place name, and an Enter / Space handler that calls `focusPoint(i)`; add a visible `:focus-visible` ring using the existing focus token.
- *Suggested command*: `$impeccable audit`

**[P1] Category on the map is colour-only**
- *Why it matters*: eight hues encode the one thing the map is for, with no legend and no text. PRODUCT.md's own accessibility line says colour is never the sole carrier. For anyone with a colour-vision deficiency, three of the eight (coral, brunch amber, sweet orange) collapse into one.
- *Fix*: cheapest honest version — when a family is open, render its pins filled and everything else as hollow rings, so the encoding is shape plus colour. Add a small legend to the map for the open family, or label the selected pin.
- *Suggested command*: `$impeccable colorize`

**[P2] The map is 227 equal dots**
- *Why it matters*: at city zoom the pins overlap into a blanket. A reader cannot tell a dense street from a single place, and clicking is a lottery in Gràcia.
- *Fix*: cluster below zoom 14 with a count bubble that zooms in on click, and keep the fan-out behaviour for identical coordinates above it. Airbnb's equivalent is the price label; ours is the count.
- *Suggested command*: `$impeccable craft map clustering`

**[P2] Two browse surfaces**
- *Why it matters*: the List overlay was built when the sidebar was a 340px column. Now the grid does the same job with different chrome, different card shape, and a second copy of the filter rail. Consistency 2/4 comes almost entirely from this.
- *Fix*: either retire the overlay and let the grid be the list, or give the overlay a job the grid cannot do (a dense table with barrio and tag columns, sortable).
- *Suggested command*: `$impeccable distill`

**[P2] White on Rausch is 3.5:1**
- *Why it matters*: the picked chip and the primary button are white text on `#ff385c` at 14px / 500, which is 3.52:1 — below the 4.5:1 body-text threshold. Every other text pair on the page passes comfortably (note 10.2, tip and pending 6.1, links 14.6).
- *Fix*: darken the chip fill to the press colour `#e00b41` (≈4.6:1 with white) or keep Rausch and set chip labels to 15px / 600, which moves them into the large-text band.
- *Suggested command*: `$impeccable audit`

## Persona Red Flags

**Jordan (first-timer, on the street in Gràcia)**: opens the link on a phone, gets the landing screen, taps a family, then has to find that the sheet pulls up to read anything. Nothing on the map says a pin is tappable; nothing on a card says it is either. The barrio tiles say "67 places" but not where that is relative to them, and there is no "near me".

**Alex (power user, planning a trip at a desk)**: cannot Tab through results, cannot hit Enter on a place, cannot open a place in a new tab from the keyboard. The search field has no label, so a screen reader announces "edit text". No way to sort. No way to see two families at once now that families are exclusive, which is right for browsing but frustrating when comparing.

**Jan (the author, adding content)**: the list view's "without a note (111)" toggle still exists and is the only writing tool in the interface; it sits inside the surface that is otherwise redundant.

## Minor Observations

- The page loads a Google Fonts stylesheet for Inter and then uses `Circular, -apple-system, system-ui`. Delete the two `<link>` tags or use the font.
- "A hand-picked map of independent spots" and "227 places, hand-picked" sit 40px apart and say the same thing.
- `PRODUCT.md`'s design principle still describes the Framer register ("near-black artboard, gradient spotlight card"), which no longer matches this branch.
- Chips are 36px tall; the WCAG comfortable target is 44. With 8px gaps this is usable, but the sub-row chips at 32px are below it.
- `3D` is an unlabelled toggle whose effect (pitch) is invisible until pressed.
- The map has no reset-view control after a zoom.
- Markers carry `title` and `aria-label` but are not focusable, so the map is keyboard-inert. That is acceptable only if the cards are operable, which today they are not.
